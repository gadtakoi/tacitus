# План проекта Tacitus

## 1. Цель

Развернуть минимальный проект **Hello World** на базе **FastAPI** в контейнеризованном окружении **Docker Compose** с
обратным прокси **Nginx** и полностью автоматизированным деплоем через **Ansible**.

Конечный результат: при обращении к корневому URL развернутого сервиса возвращается JSON-ответ
`{"message": "Hello World"}`.

---

## 2. Архитектура

```
┌─────────────┐
│   Client    │
└──────┬──────┘
       │ HTTP
       ▼
┌─────────────┐     ┌───────────────────┐
│    Nginx    │────▶│  FastAPI (Uvicorn)│
│  (reverse   │     │   "Hello World"   │
│   proxy)    │     └───────────────────┘
└─────────────┘            ▲
       │                   │
       └───────────────────┘
          Docker Compose
```

### Компоненты

| Компонент   | Назначение                                     |
|-------------|------------------------------------------------|
| **Nginx**   | Обратный прокси, терминация HTTP, балансировка |
| **FastAPI** | ASGI-приложение на Python 3.14+, endpoint `/`  |
| **Docker**  | Контейнеризация сервисов                       |
| **Ansible** | Автоматизация подготовки хоста и запуска стека |

## 5. Требования

### Функциональные (FR)

- **FR-001**: При `GET /` приложение возвращает JSON `{"message": "Hello World"}`.
- **FR-002**: Nginx проксирует внешние HTTP-запросы к FastAPI.
- **FR-003**: Ansible обеспечивает полный цикл развертывания на чистом хосте.

### Нефункциональные (NFR)

- **NFR-001**: Время отклика endpoint `/` не более 100 мс при локальном запросе.
- **NFR-002**: Приложение корректно обрабатывает ошибки без падения.
- **NFR-003**: Все изменения воспроизводимы и idempotent.
- **NFR-004**: Нет секретов в коде, конфигурации и логах (согласно `security-rules.md`).
- **NFR-005**: Логи содержат `request_id`, route, статус ответа, но не содержат чувствительных данных.

## 7. Риски и ограничения

| Риск                          | Митигация                                                |
|-------------------------------|----------------------------------------------------------|
| Несовместимость версий Docker | Фиксировать версии, тестировать на целевом хосте         |
| Утечка секретов в репозиторий | Использовать `.gitignore`, secret manager для production |
| Ansible не идемпотентен       | Проверять `changed=0` при повторном прогоне              |
| Конфликт портов               | Параметризовать порты через `group_vars`                 |
| Отсутствие rollback           | Добавить `docker compose down` + backup логики           |
