# План проекта Tacitus — доступ к архиву, учётные записи и эксплуатация

> **Статус: выполняется.** Создан 2026-09-10; закрыты A1 (ADR-018) и A2 (ADR-019).
>
> План выполняется пошагово: этапы A → B, внутри этапа — по пунктам. Каждый пункт закрывается отдельным коммитом, в
> котором вместе с кодом обновляются тесты, документация и ТЗ (`docs/ToR_Tacitus_v1.0.md`, навык `tor-sync`).

## 1. Цель

Закрыть три группы пробелов, найденных при сплошном осмотре репозитория 2026-09-10:

1. **Данные недоступны или неограничены.** Записи, уехавшие в S3, нельзя получить обратно через API; список файлов
   отдаётся целиком без пагинации; зарегистрироваться может кто угодно, а ролей нет; отключение учётной записи не
   прекращает уже выданную сессию.
2. **Эксплуатация держится на ручных действиях.** Нет CI, нет автоматических бэкапов БД, нет проверки живости
   зависимостей, журнал безопасности читается только SQL-ом.
3. **Функциональность видеосервиса не доведена до пользователя.** Архив и живой поток нельзя посмотреть в интерфейсе.

**Конечный результат этапа A:** цикл «поток → запись → архив → просмотр/выгрузка» замкнут, доступ к нему ограничен явно
управляемым множеством учётных записей, а сборка и бэкапы выполняются без участия человека.

> **Важно:** план не объединяется с `plan/PLAN.md` и прочими `PLAN_stage_*.md`. Ролевая модель (RBAC), владение
> объектами и SSO в объём **не входят** — см. §6.

учётных записей, а не правами).

## 4. Этап A — нужно

### A1. Доступ к архиву записей через API

**Контекст.** Записи уезжают в S3 и становятся недостижимыми: ключ содержит `/`, а единственный эндпоинт выдачи ссылки
работает только с плоским именем. Продуктовый цикл обрывается на последнем шаге.

**Решение.** Отдельный ресурс `/recordings` поверх того же бакета, с ключом-путём и жёстко ограниченным префиксом.
`/files/*` не трогаем — у него другой контракт (санитизация имени, белый список типов и расширений).

- [x] Добавить настройку `s3_archive_prefix: str = "mediamtx-archives/"` в `app/core/config.py` с docstring и внести её
  в `_FIELD_GROUPS` (`app/services/settings_service.py`) — иначе она попадёт в группу «Прочее».
- [x] Добавить в `app/services/s3_service.py`:
    - [x] `sanitize_object_key(key: str, allowed_prefix: str) -> str` — отдельно от `sanitize_filename`: нормализация
      `\` → `/`, запрет `\x00`, `..`, ведущего `/`, обязательный префикс `allowed_prefix`, ограничение длины;
    - [x] `list_objects(prefix, limit, cursor)` — одна страница `list_objects_v2` с `MaxKeys` и `ContinuationToken`,
      возврат `(items, next_cursor)`;
    - [x] `get_presigned_url` — принимает произвольный ключ (проверка префикса остаётся на вызывающем коде, как и для
      `/files`).
- [x] Создать `app/schemas/recordings.py`: `RecordingItem` (ключ, поток, размер, время изменения),
  `RecordingListResponse` (`items`, `next_cursor`).
- [x] Создать `app/api/routers/recordings.py` (`prefix="/recordings"`):
    - [x] `GET /recordings` — фильтры `stream`, `limit`, `cursor`; лимит `60/минуту` по `get_user_or_ip`;
    - [x] `GET /recordings/{key:path}` — presigned URL, `head_object` перед выдачей, 404 при отсутствии; лимит

    - [x] `DELETE /recordings/{key:path}` — лимит `10/минуту`;

    - [x] TTL ссылки соответствует `presigned_url_expiration` (mock);
    - [x] `recording.download` попадает в журнал безопасности.
- [x] Документация: `docs/backend.md` (раздел «Записи»), `docs/security.md` (таблицы rate limits и security events),

### A4. `is_active` действует на всю сессию

**Контекст.** Флаг проверяется только при логине. Отключённый пользователь продолжает работать по действующему
access-токену и продлевает сессию через `/auth/refresh` бесконечно — каждая ротация выдаёт новый 7-дневный токен.

- [ ] `UserRepository` — метод получения активности по `username` (одним запросом, без загрузки связей).
- [ ] `get_current_user` (`app/api/dependencies.py`) — после проверки отзыва сверять `is_active`, при `False` → 401 и
  событие `auth.inactive_user`.
- [ ] `rotate_refresh_token` — та же проверка перед выдачей новой пары; при отказе отзывать всё семейство токенов.
- [ ] Замерить цену: сессия к БД в запросе уже открыта (проверка `revoked_tokens`), добавляется один `SELECT`. Если в
  проверке под нагрузкой это заметно — зафиксировать решение в ADR-020, а не вводить кэш «на всякий случай».
- [ ] Тесты: отключение пользователя рвёт доступ по существующему access-токену и запрещает ротацию.
- [ ] ТЗ: требования аутентификации — «отключение учётной записи прекращает действующие сессии».

### A5. Смена пароля и отключение учётной записи

**Контекст.** `UserRepository` умеет только создавать и искать. Сменить пароль или отключить аккаунт можно
исключительно SQL-ом на сервере.

- [ ] `UserRepository.update_password`, `UserRepository.set_active`.
- [ ] `POST /auth/password` — текущий и новый пароль, лимит `5/minute`, проверка текущего пароля, отзыв **всех**
  refresh-токенов пользователя и текущего access-токена (`jti` → `revoked_tokens`), событие `auth.password.changed`.
  Границы длины — те же, что при регистрации (`tests/test_password_bounds.py`).
- [ ] `scripts/init_project.py` — подкоманды `--disable <username>` и `--enable <username>` (отключение отзывает
  семейство токенов); `scripts/init.sh` прокидывает их внутрь контейнера.
- [ ] Тесты: смена пароля инвалидирует старую сессию; неверный текущий пароль → 400; отключение через CLI рвёт доступ
  (совместно с A4).
- [ ] Документация: `docs/backend.md` (в таблице репозиториев заменить строку «update/delete не реализованы»),
  `docs/security.md`, `README.md`, `docs/deployment.md` (эксплуатационные команды); ТЗ — §8 и таблица ролей.
- [ ] ADR-020 «Модель учётных записей: управляемая регистрация, отключение, смена пароля» (покрывает A3–A5).

## 7. Порядок выполнения

A1 → A2 (второй опирается на префикс и постраничный листинг из первого) → A3 → A4 → A5 (общая ADR-020, общие тесты

## 8. Критерии приёмки этапа A

- [ ] Архивный сегмент, выгруженный `mediamtx-archive-manager`, скачивается через API и удаляется через API; попытка
  выйти за префикс архива даёт 400.
- [ ] `GET /files/` отдаёт страницу фиксированного размера с курсором и не содержит ключей архива.
- [ ] При `TACITUS_REGISTRATION_ENABLED=false` регистрация отвечает 403 и пишет событие; в развёрнутом стеке флаг
  выключен по умолчанию.
- [ ] Отключение учётной записи немедленно прекращает доступ по выданному access-токену и делает ротацию невозможной.
- [ ] Пользователь может сменить себе пароль; после смены все прежние сессии недействительны.
- [ ] CI на каждый push прогоняет линт, типы, тесты с реальной БД и сборку фронтенда; ни один БД-тест не пропущен.
- [ ] Бэкап базы снимается автоматически, уезжает в S3, старые копии удаляются, восстановление проверено по
  документированной процедуре.
- [ ] `docs/ToR_Tacitus_v1.0.md` описывает всё перечисленное как требования, а `plan/DECISIONS.md` содержит ADR-018,
  ADR-019 и ADR-020.

## 9. Риски и ограничения

| Риск                                                                                  | Смягчение                                                                                           |
|---------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------|
| Ключ-путь в `/recordings/{key:path}` — классический вектор обхода                     | Отдельная функция санитизации с обязательным префиксом и негативные тесты в A1 до реализации выдачи |
| Проверка `is_active` добавляет запрос к БД на каждый вызов                            | Сессия уже открыта ради `revoked_tokens`; при заметной цене — решение и замер в ADR-020             |
| Изменение контракта `GET /files/` ломает фронтенд                                     | Поле `files` сохраняется, `next_cursor` добавляется; фронтенд правится тем же коммитом              |
| CI с реальной БД удлиняет обратную связь                                              | БД-сервис поднимается один раз на job; локальный прогон без БД остаётся прежним                     |
| Бэкап уезжает в тот же S3, что и данные приложения                                    | Отдельный префикс сейчас; вынос в отдельный бакет — при появлении требований к RPO/RTO              |
| Отключение регистрации закрывает единственный способ завести пользователя в production | `scripts/init.sh` уже заводит учётную запись идемпотентно — проверить это в A3                      |
