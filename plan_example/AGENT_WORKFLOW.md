# Рабочий процесс агента

## Назначение
Этот документ описывает правила и процесс взаимодействия AI-агента с проектом Tacitus.

## Общие принципы

1. **Минимальные изменения** — вносить только необходимые правки, не переписывать код без причины
2. **Тестирование** — проверять изменения перед завершением задачи
3. **Документирование** — обновлять документацию при изменении архитектуры или интерфейсов
4. **Ясность** — писать понятный, поддерживаемый код

## Процесс работы

### 1. Получение задачи
- Проанализировать запрос
- Задать уточняющие вопросы при необходимости
- Оценить объём работы

### 2. Исследование
- Изучить связанные файлы и модули
- Проверить существующие тесты
- Оценить влияние изменений

### 3. Реализация
- Создать ветку (при работе с git)
- Внести изменения согласно стилю проекта
- Написать или обновить тесты
- Обновить документацию

### 4. Проверка
- Запустить тесты: `pytest`
- Проверить линтеры: `ruff check .`
- Убедиться в отсутствии регрессий

### 5. Завершение
- Создать commit с понятным сообщением
- Создать PR при необходимости
- Обновить TASKS.md

## Стиль кода

- Форматирование: PEP 8
- Линтер: Ruff
- Типизация: использовать аннотации типов (PEP 484)
- Докстринги: Google-style или NumPy-style

## Ограничения

- Не коммитить напрямую в main/master без согласования
- Не добавлять секреты и чувствительные данные
- Не удалять файлы без подтверждения
- Не устанавливать зависимости глобально — только в виртуальное окружение проекта

## Обновление процесса

Изменения в этом документе вносятся по согласованию с владельцем проекта.
